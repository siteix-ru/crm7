# UI: дизайн-система (Ant Design)

Интерфейс приводится к рекомендациям Ant Design. Общие токены — в
`frontend/src/app.css` (`:root`); компоненты — в `frontend/src/lib/components/ui/`.

Правила переноса этого эталона на другие списки — в [`list-rollout.md`](list-rollout.md).

## Токены

Цвета:
- Основной: `--primary #0958d9`, `--primary-hover #0a54cf` (≥4.5:1 к `--on-primary`), `--primary-active #003eb3`, `--primary-bg #e6f4ff`, `--primary-border #91caff`, `--on-primary`.
- Текст: `--text rgba(0,0,0,.88)`, `--muted rgba(0,0,0,.65)`, `--text-description rgba(0,0,0,.55)`.
- Границы/заливки: `--border #e2e5ea`, `--border-secondary #f0f0f0`, `--fill-tertiary rgba(0,0,0,.02)`, `--fill-hover rgba(0,0,0,.06)`, `--focus-soft` (контрастный внутренний акцент фокуса).
- Статусы: `--danger`, `--danger-bg`, `--error-border`, `--error-text #cf1322`; `--success`, `--success-bg`, `--success-border`, `--success-text #389e0d`; `--warning`, `--warning-bg`, `--warning-text #d48806`.

Прочее:
- Радиусы: `--radius-sm 8px`, `--radius-md 12px`. Тени: `--shadow-sm`, `--shadow-md`.
- Отступы: `--space-1..6` = 4/8/12/16/24/32. Контролы: `--control-height 32px`,
  `--control-height-lg 40px` (36 в compact, 44 на тач-устройствах);
  `--field-label-gap`, `--field-grid-gap`, `--filters-group-gap`.
- Шрифт: `--font` (системный), база 14px / line-height 1.5714.

**Правило:** не хардкодить цвета вне токенов Ant — использовать переменные.

## Размеры

- Контролы — **32px** (`--control-height`); в модалках фильтров и их кнопках —
  **40px** (`--control-height-lg`, compact 36, тач 44).
- Иконки внутри кнопок — **16px**.
- Радиус контролов — 8px; карточек, модалок и панелей — 12px.
- Фокус полей — контрастный внутренний акцент `box-shadow: inset 0 0 0 2px var(--focus-soft)`
  и `--primary-border`; внешний outline с positive offset запрещён (обрезается).

## Иконки

- `frontend/src/lib/components/ui/Icon.svelte` — карта имён → иконки из `@ant-design/icons-svg`.
- Использование: `<Icon name="edit" size={16} />`.
- Иконка рендерится как `<svg fill="currentColor">` — цвет задаётся через `color` родителя.
- **Добавить иконку:** импортировать `XxxOutlined`/`XxxFilled` из `@ant-design/icons-svg/es/asn/...`
  и добавить запись в объект `icons` (ключ — короткое имя).
- Текущие имена: `admin`, `arrow-*`, `bell`, `camera`, `cart`, `chat`, `check-circle`, `clients`,
  `close`, `close-circle`, `edit`, `export`, `group`, `help`, `import`, `info`, `my-reports`,
  `picture`, `plus`, `reports`, `requests`, `settings`, `sort`, `stocks`, `substitutions`, `view`.

## Компоненты (`frontend/src/lib/components/ui/`)

- **`Button.svelte`** — `variant: 'primary' | 'success' | 'ghost' | 'text' | 'danger'` (по умолч. `primary`;
  `success` — мягкое позитивное действие), `size: 'sm' | 'md' | 'lg'` (32/40px), `loading`, `disabled`, `title`, `ariaLabel`, `onclick`.
- **`Modal.svelte`** — общий шелл: `open`, `title`, `label`, `size: 'sm'|'md'|'lg'`, `wide`/`width` (deprecated), `closeButton`, `bodyMinHeight`, `onclose`.
  Рендерится только при `open`; Escape и клик по маске закрывают.
- **`Input.svelte`** — `label`, `type`, `value` (bindable), `placeholder`, `error`, `name`, `inputmode`,
  `min`, `max`, `step`, `maxlength`, `id`, `ariaLabel`, `ariaInvalid`, `ariaDescribedby`. Высота 32.
- **`Select.svelte`** — `label`, `value` (bindable), `disabled`, `id`, `ariaLabel`, `ariaInvalid`,
  `ariaDescribedby`; опции передаются слотами. Высота 32.
- **`Textarea.svelte`** — `label`, `value` (bindable), `rows`, `maxlength`, `disabled`, `id`, `ariaLabel`,
  `ariaInvalid`, `ariaDescribedby`.
- **`SearchInput.svelte`** — поиск с историей (`historyKey`), `onclear`, `onpick`.
- **`Spinner.svelte`** — `size` (по умолч. 18).
- **`Pagination.svelte`** — `page`, `perPage`, `total`, `onchange`, `onperpage`, `perPageOptions`, `always`, `loading`.
- **`FiltersModal.svelte`** — кнопка «Фильтры» + модалка (`onapply`, `onreset`, `onopen`, `count`,
  `size`, `dirty`, `resetLabel`, `show()`, `announce()`). announce — скрытый `role="status"`
рядом с диалогом (переживает закрытие); `onapply`/`onreset` могут вернуть строку — модалка
объявит её сама.
- **`ExportModal.svelte`** — выбор формата (XLSX/XLS/CSV/TXT/PDF) и способа (скачать/почта), `onpick(format, byEmail)`.
- **`Logo.svelte`**, **`BarChart.svelte`** — логотип и гистограмма.
- **`stocks/PhotoGallery.svelte`** — галерея фото: `photos`, `variant: 'list' | 'tile'` (tile — свайп/стрелки), `onopen`, `flush`. Пропорции/вписывание и размер запрашиваемого варианта берутся из настроек (список → `preview`, tile → `card`).

## Склады

Страница «Склады» (пункт навигации, если включён `module.warehouses` и есть `stocks.import`/`stocks.edit`)
оформлена как «Номенклатура»: тулбар `[Сортировка][Отображение] │ [Добавить][Экспорт] │ [Хелп]`, два вида
(таблица с шапкой и сортировкой по клику + плитки), блок перелистывания внизу, фоновое автообновление
(`config.listPollMs`, 30 с). Счётчика складов нет; фото у складов нет, поэтому опций «с фото» нет. Под
названием — тип (если не «основной»), адрес и ответственный; у «основного» склада — тег «основной».

Карточка склада — три вкладки:

- **Основное** — реквизиты (`Название`, `Название в 1С`, `Номер`, `Порядок`), тип (селект) и ответственный
  (кнопка-контрол → модалка-пикер: поиск + список, выбор только среди менеджеров и администраторов),
  флаги: «Основной склад», «Доступен для заявок и самовывоза» (если включён модуль «Заявки»),
  «Учитывать в отчётах» (если включён модуль «Отчёты»), «Активен (показывать позиции на этом складе)»;
- **Контакты** — адрес, контактное лицо, телефон, e-mail, комментарий;
- **Доступ** — роли склада (`stocks.LEVEL`, чекбоксы Сисадмин/Администратор/Менеджер/Клиент) и персональный
  список пользователей (убрать с подтверждением).

Скрытый склад не виден пользователям, но импорт на него идёт. Добавление доступа — модалка-пикер: таблица
пользователей (ФИО / логин / роль / доступ) с поиском, фильтром по ролям (Сисадмин/Администратор/Менеджер)
и сортировкой по клику; показываются активные пользователи выбранных ролей, а те, у кого доступ уже есть,
помечены тегом «есть доступ» (`GET /stocks/warehouses/{id}/candidates`). Кнопка «Добавить» и тег «есть
доступ» — одного размера (Ant small, 24px). Добавление склада — отдельная страница `#/warehouses/new`
(та же карточка в режиме создания: вкладки «Основное»/«Контакты», без «Доступа»; «Создать» →
`POST /stocks/warehouses` → переход в карточку). Экспорт списка — `ExportModal` →
`GET /stocks/warehouses?export=<format>`. При отключённом модуле склады не отображаются (один
«виртуальный» склад).

## Фото номенклатуры

Формат отображения — системная настройка (`#/settings` → «Система»); применяется к плиткам, строкам, карточке позиции и ItemEdit:

- **формат** (`stocks.photo_ratio`): динамический (по фото) / квадрат 1:1 / горизонтальный 4:3 / вертикальный 3:4;
- **несовпадение пропорций** (`stocks.photo_fit`): вписывать (без обрезки, по умолчанию) / заполнять (с обрезкой);
- **размеры вариантов** по длинной стороне, px (`stocks.photo_size_preview/card/max`, дефолт 160/600/1600).

Список запрашивает `preview`, плитки/карточка/просмотр — `card`, полный размер — `max`. При загрузке фото уменьшается до `max` и генерируются варианты `card`/`preview` (см. [`architecture.md`](architecture.md)).

## Карточка позиции

`#/stocks/items/:id/edit`; создание — `#/stocks/items/new` (без выбора склада: позиция общая, остатки
задаются после создания). Позиция единая для всех складов: вкладка «Основное» — тип позиции (только
разрешённые типы), общие поля (название, артикул, единица измерения — селект из основных единиц, группа,
описание) и цены текущего склада; вкладка «Количество» — общий остаток и список **всех доступных складов**
(остаток можно задать на любом — уровень создаётся при сохранении, текущий отмечен тегом); вкладка
«Состав» (у набора) — список компонентов с количеством, добавление через пикер поиска по
названию/артикулу. Переименование меняет позицию на всех складах. В шапке — статус «деактивирована» и
кнопки «Деактивировать/Активировать» (право `stocks.deactivate`) и «Удалить» (право `stocks.manage`;
причина запрета — в подсказке кнопки). Табы — подчёркиванием (как в карточке склада).

Деактивированные позиции в списке номенклатуры подсвечены фоном и тегом «деактивирована»; в модалке
«Сортировка» роли с правом доступен блок «Показывать: Все/Активные/Неактивные» (у остальных — только
активные). У деактивированной позиции скрыты кнопки корзины.

**Группы номенклатуры** — `#/stocks/groups` (иконка `tags` в тулбаре «Номенклатуры», право
`settings.manage`): таблица групп (название, описание, позиций); «Добавить группу» и «Редактировать»
ведут на отдельную страницу `#/stocks/groups/:id` (название и описание, состав группы, сохранение и
удаление там же; позиции остаются «без группы»). Включение модуля — чекбокс «Разрешить использовать
группы позиций» в «Настройках»; группа назначается позиции в редактировании и используется в фильтрах
остатков и выбора позиций в заявке.

## Настройки

`#/settings` — шесть вкладок: **Общие · Модули · Почта · Документы · База данных · Обновления**. «Общие» объединяют
брендинг и юридические реквизиты с настройками продаж, склада, цен, групп и фото. Вкладка «Почта» видна
при `mail.manage` или `mail.send`: SMTP и тест соединения доступны по `mail.manage`, а шаблоны писем,
очередь и расписания отчётов — по `mail.send`. Право `mail.recovery` отдельно и используется для
восстановления доступа. «Документы» — редактор юридических текстов, «База данных» — параметры подключения.

Управление пользователями — единственная страница `#/staff` (`users.manage`); отдельной страницы
«Роли» нет, тонкая матрица `level_capabilities` меняется через `POST /roles/{level}` (`roles.manage`).
Журнал аудита доступен по `#/admin/audit` при `audit.view` (уровни 90 и 50); проверка по числовому
уровню в UI и API не используется.

Все сотрудники (`LEVEL >= 10`) просматривают всех клиентов и все заявки: `#/clients`, карточки
клиентов, `#/requests`, карточки заявок и экспорт не ограничиваются закреплением менеджера.
Фильтры «В работе у меня / у других» — средство навигации, а не граница доступа. Клиент (`LEVEL 5`)
видит только свои заявки. Права `requests.view.own` / `clients.view.own` в матрице ролей устарели и
не ограничивают просмотр; `view.all` дополнительно влияет на чаты, замещения и флаги управления.
Политика доступа к чатам этой правкой не меняется.

Вкладка «Модули» (нужно `roles.manage`): карточки модулей — переключатель вкл/выкл, описание и
группы доступа. В каждой группе — мультивыбор ролей (Сисадмин/Администратор/Менеджер/Клиент/Гость) с
подсказкой о выдаваемых правах. Доступ ролей пишется в `level_capabilities`; менять его может только
сисадмин (`roles.manage`), остальным выбор показан отключённым. «Сохранить» — `POST /admin/modules`.

## Паттерны страниц

- **Клик по строке/плитке:** «Склады» — вся строка/плитка открывает карточку склада (название остаётся
  ссылкой для клавиатуры/новой вкладки, клик по ней не дублируется). «Номенклатура» — вся строка открывает
  карточку позиции, но корзина («Добавить», «−/+») перехватывает клик (`stopPropagation`) и карточку не
  открывает. Интерактивно только название (единственный доступный элемент) — остальные тексты (мета, статы)
  обычные; при ховере строки название подсвечивается `--primary`.
- **Поиск и возврат из карточки:** поисковый запрос и номер страницы входят в сохранённые фильтры списка
  (`stocks`/`warehouses`), поэтому при возврате из карточки список открывается на том же поиске, странице и
  фильтрах. `SearchInput` помнит последние поиски (localStorage `crm.search.<key>`) и показывает их по
  фокусу при пустом поле — на «Номенклатуре» и «Складах».
- **Отступы (канон, Ant; едино на «Номенклатуре» и «Складах»):** страница — `gap` 16 (`--space-4`);  шапка (`h1` + подзаголовок) — колонка, `gap` 4 (`--space-1`), подзаголовок без внешнего margin;
  тулбар — `gap` 16; строка списка — `padding: 12px 16px`, `gap` 12; сетка плиток — `gap` 16;
  плитка — контентный отступ 12 (`--space-3`) (у плитки с фото фото во всю ширину, внутренние отступы 12);
  блок перелистывания — `gap` 12, контролы 32px.

- **Заголовок:** `h1` 20px / 600 / `--text`; подзаголовок 14px `--text-description`.
- **Тулбар:** фильтры слева, действия справа; разделители — 1px × 24, `--border-secondary`.
- **Таблица:** шапка `--fill-tertiary`, текст 600 / `--text`, разделители `--border-secondary`,
  числа по правому краю, пагинация 32px.
- **Модалки:** заголовок 16/600, футер `[Отмена] [Действие]` справа.
- **Alert/notice:** иконка + рамка + тёмный текст на цветном фоне (`--danger-bg`/`--success-bg`).

## Бейджи страниц (только dev)

В dev-сборке в правом нижнем углу показан бейдж текущей страницы: ID и задача. Реестр —
`frontend/src/lib/dev/page-badges.ts` (`route -> { id, task }`). ID задаётся произвольно, `task` — короткая
пометка по странице; пустой ID скрывает бейдж. Клик по бейджу копирует «ID — задача». В production-сборку
компонент и реестр не попадают.

## Ширина и адаптивность

Единая сетка порогов (новые правила добавлять только в этих точках):

- **< 720 px** — телефоны: одна колонка, шторки-модалки, нижняя навигация.
- **< 400 px** — узкие телефоны: действия в шапке страницы уходят на отдельную строку, вкладки карточки занимают всю ширину, цена и сумма в составе идут двумя строками.
- **< 360 px** — свёрнутые экраны и сплит-скрин: компактная шапка приложения (иконки 30 px, аватар 28 px), отступы страницы 12 px, заголовок карточки 17 px.
- **720–1024 px** — планшеты: двухколоночные карточки (заявка, клиент) сворачиваются в одну колонку, таблицы прячут второстепенные столбцы.
- **1024–1600 px** — ноутбуки и десктопы: контейнер 1280 px.
- **≥ 1600 px** — контейнер списков и таблиц 1440 px.
- **≥ 1920 px** — контейнер списков и таблиц 1600 px.

Списки и таблицы помечаются классом `page-wide` («Заявки», «Клиенты», «Сотрудники», «Номенклатура»,
карточка заявки), страницы на всю ширину — `page-full` («Настройки»). Обычные страницы и формы
остаются 1280 px. Расширение для `page-wide` задаётся в `app.css`, локальные `max-width` у страниц
не нужны.

Кнопки в подвале модалок (`.modal-actions` / `.modal-buttons`) на экранах ≤ 720 px распределяются
в один ряд равной ширины (общее правило в `app.css`, локальные `flex-wrap: wrap` его не перебивают).
На ≤ 480 px последняя кнопка переносится в отдельный ряд на всю ширину, чтобы длинные подписи не
обрезались; это тоже общее правило `app.css`, а не исключение конкретной страницы.

Мобильное правило должно повторять селектор базового: если на десктопе сетка задана как
`.it-row.prices`, то в медиазапросе `.it-row { grid-template-columns: ... }` её не перебьёт
(специфичность ниже) — пишите `.it-row, .it-row.prices`. Такие переопределения держим в конце
`<style>`, после базовых правил.

Нижняя навигация на телефоне — единственное меню приложения: до четырёх основных разделов +
«Ещё» (иконка `menu`). «Ещё» открывает боковую панель с двумя группами — «Разделы» (прочие
разделы) и «Сервис» (чат, корзина, «О программе», журнал; бейджи непрочитанного на пунктах и
суммарный бейдж на кнопке «Ещё»). Шапка на мобильном меню не дублирует: только логотип,
иконка уведомлений и аватар (чат/корзина/«О программе»/журнал скрыты). Панель закрывается по
переходу, по Escape, по фону и при расширении окна выше 720 px (matchMedia). Состав собирается
в `AppShell.svelte` (`mobileNavItems` + `mobileServices`), подписи в баре обрезаются
многоточием и не вызывают горизонтальный скролл.

Мобильная композиция страниц (≤720 px): списки показывают карточки («Заявки», «Номенклатура»,
«Клиенты», «Склады», «Сотрудники», «Замещения» — период второй строкой), справочные таблицы
(типы, группы, типы цен) сжимаются без горизонтального скролла (типы и типы цен прячут
колонку «Код»), остатки
по складам в карточке номенклатуры идут карточкой (склад и корзина в строке, цены и остаток
строками ниже), карточки модулей в админке — в одну колонку.

## Шапка страницы (`PageToolbar`)

Единый каркас для списковых страниц (REQ-LIST, CLI-LIST, STK-LIST, WH-LIST, STAFF-LIST,
STAFF-SUBST, STK-IMPORT, REP-LIST):

- `<PageToolbar>` — **плоская** шапка: без фона, рамки и разделителя. Группировку создают
  сами контролы и карточка/список ниже. `page-hero` для списков устарел.
- Слева — `leading` (только реальная навигация назад) и ровно один `h1` (`title` — строка
  или сниппет). `<header>` связан с заголовком через `aria-labelledby`.
- Справа — `actions` (`role="group"` с `aria-label`). В эталоне CLI-LIST все действия,
  включая CTA «Новый клиент», лежат в одном `ToolbarMenu`; отдельный слот `primary`
  остаётся доступным, но в списках сейчас не используется. Порядок пунктов меню:
  поиск → сортировка → вид/фильтры → утилиты → CTA.
- `tabs` — отдельный именованный регион для переключения видов одного экрана, **не** actions.
  Маршруты (`/staff` ↔ `/substitutions`) — ссылки с `aria-current`, не ARIA-вкладки.
- Все действия списка находятся в **одном** `ToolbarMenu` (кнопка «Ещё»): сортировка,
  вид/фильтры, утилиты и создание. Переключаемые пункты — `role="menuitemcheckbox"` с
  `aria-checked`; тяжёлые модалки (фильтры) открываются через `FiltersModal.show()`.
- Поиск тоже живёт в `ToolbarMenu`: пункт «Поиск» открывает общую модалку с подсказками
  из истории (`getHistory`) и названий загруженных записей. Запуск — только по «Найти»;
  пока идёт запрос, показывается плавающий лоадер с «Остановить» и таймаутом 15 с.
  При активном поиске рядом с «Ещё» показывается чип `Поиск: …` с кнопкой очистки.
- Адаптив ≤720 px: заголовок отдельной строкой, затем поиск/действия; компактная кнопка
  «Ещё» сохраняет область нажатия 44 px и `aria-label`. Отступы и высоты — только токены
  (`--space-*`, `--control-height`), цвета — только токены (`--on-primary` для текста на `--primary`).
- Фокус: контрастный внутренний акцент 2 px (`--focus-soft`) через `box-shadow: inset`,
  не внешний контур с positive offset — он обрезается краями поля.

## Эталонная модалка фильтров

`FiltersModal` + `Modal` — единый каркас для всех модалок фильтрации (эталон — CLI-LIST):

- Размер задаётся `size: 'sm' | 'md' | 'lg'` (560 / 640 / 780 px). `width` и `wide`
  остаются только для обратной совместимости; новые страницы используют `size`.
- Высота контролов и кнопок — `--control-height-lg` (40 px, 36 px в compact),
  внутренний padding `--space-4`; отступ подписи — `--field-label-gap`, между
  группами — `--filters-group-gap`. Локальные `:global()`-переопределения на страницах
  запрещены: значения живут в общих компонентах и токенах.
- Порядок блоков: статусы → менеджеры → города → даты. Даты — две колонки с общим
  заголовком «Дата регистрации» и подписями «Дата регистрации с/по».
- Группы разделяются тонкой линией `--border-secondary`; подвал `.modal-actions`
  липкий, с фоном `--surface` и safe-area. «Сбросить» (text, `size="lg"`) стоит у левого
  края, «Отмена» (ghost) и «Применить» (primary) — в правой группе `.modal-buttons`
  в этом порядке; все кнопки `size="lg"`. `resetLabel` по умолчанию «Сбросить»,
  эталон использует «Сбросить всё».
- `MultiSelect` внутри модалки: `size="lg"`, `aria-haspopup="dialog"`, `aria-controls`,
  имя триггера включает выбранное, фокус при открытии переходит к первому чекбоксу,
  Escape закрывает только поповер; цели ≥44 px при `(pointer: coarse)`.
- `SortDialog` — общая модалка сортировки для всех списков (CLI-LIST, `Staff`, заявки
  в карточке клиента): по одному циклическому переключателю на поле
  (`выкл → ↑ → ↓ → выкл`), порядок условий — по порядку включения; drag и кнопки
  приоритета удалены. `size="md"`, кнопки единой высоты, анонс полного порядка внутри диалога.
- `Modal` принимает `announcement`: live-регион рендерится **внутри** `role="dialog"`,
  иначе `aria-modal="true"` может скрыть анонс от скринридера. Вне диалога остаётся
  страничный `role="status"` — для действий тулбара и для результатов, получаемых после
  закрытия модалки (такой регион имеет `aria-hidden={open}`).
- Осознанные компромиссы CLI-LIST как эталона: поиск и создание живут в `ToolbarMenu`
  (единый паттерн «все действия в «Ещё»»); брейкпоинты 1200/1024/900/720 для таблицы
  клиентов — локальное исключение из общего канона 1024/1600.
- Применение фильтров обновляет скрытый `role="status"` («Фильтры применены. Найдено: N»);
  «Сбросить» очищает значения и сразу применяет их.
- Тёмная тема использует только токены (`color-scheme: dark`, `--on-primary` для бейджей,
  `--muted`/`--fill-hover` для кнопки закрытия).

### Исключения раскатки (волна 1)

- `Warehouses`, `StockTypes`, `PriceTypes`, `StockGroups` — короткие справочники: API не
  принимает `q`/`sort`, поэтому поиск и `SortDialog` не добавляются. Таблицы строятся по
  дескрипторам из `lib/views/directory-fields.ts`; на мобильном колонка «Код» скрывается,
  но её значение входит в `aria-label` ссылки.
- `StockGroups` — при `groupsConfigured === false` маршрут `/stocks/groups` закрыт на уровне
  `App.svelte` и отдаёт `NotFound`; в странице нет собственного состояния «модуль выключен».
- `AdminAudit` — журнал событий, а не таблица: разметка `role="list"`/`role="listitem"` с
  программными подписями полей. Сервер не поддерживает сортировку, поэтому `SortDialog`
  не используется. Поиск фильтрует точным кодом действия (`request.transition`), подсказки
  показывают коды, а не human-readable подписи.
- `AdminAudit` и справочники не требуют split-модалки «Вид»: набора полей/видов у них нет.

### Исключения волны 2 (Staff)

- `Staff` — двухвкладочная страница: общий тулбар обслуживает и список сотрудников, и
  встроенный список замещений (`Substitutions` с пропсом `embedded`), который фильтруется
  в памяти и не имеет собственной пагинации. Вид и фильтры разделены на отдельные модалки,
  но для вкладки замещений «Вид» содержит только переключатель списка/плиток.
- `Staff` — legacy-записи без `viewExplicit` трактуются как явный выбор (`initialStaffViewMode`),
  чтобы сохранённый до обновления вид не терялся.
- Реестр полей `Staff` — `lib/views/staff-fields.ts`; подписи обязательных колонок, наборы
  колонок и строки плиток выводятся из него. `Substitutions` не получает отдельный реестр,
  пока остаётся встроенным списком.

### Исключения волны 2 (Requests)

- Реестр полей `Requests` — `lib/views/request-fields.ts`. Клиент доступен только сотрудникам
  (`staffOnly`) и дополнительно скрывается на узких экранах; обе проверки живут в реестре.
- Локальная сортировка по клику на шапку удалена: все условия задаются только в `SortDialog`,
  который закрывается по «Применить». Иначе дублировались бы два механизма с разными приоритетами.
- «Фильтры» в тулбаре показывают счётчик активных условий; «Вид» — отдельная модалка с полями
  списка и плиток и мгновенным применением.

### Исключения волны 3

- `Stocks` — три режима (`list/tiles/columns`) и два ключа размера страницы (`per_page_list`,
  `per_page_tiles`) сохранены как есть: их объединение потребует миграции сохранённых настроек.
  Режим `columns` сортируется локально по колонкам складов (кликабельные шапки) — это
  осознанное исключение из правила «только `SortDialog`»: серверный whitelist понимает только
  `warehouse`, поэтому поля `warehouse_<id>` в общий диалог не включаются.
- `StockLots` — фильтры вынесены в общий `FiltersModal`, но API не поддерживает сортировку и
  принудительно заменяет `per_page<=0` на 50. Поэтому `SortDialog` и режим «Все» здесь не
  добавляются: это было бы мёртвое управление.
- `StockLots` — нет режима «Вид» и набора полей: таблица партий фиксирована, поэтому вторая
  модалка не создаётся.

## Реестр полей списка

`frontend/src/lib/views/client-fields.ts` — единственное описание поля для CLI-LIST: подпись
в чекбоксе «Вид», колонка таблицы (`headClass`/`cellClass`/`width`/`value`), зона плитки
(`tileRegion`: `title`/`row`/`foot`) и мета-строка мобильного списка. Необязательные колонки,
их шапки, ячейки и плитки рендерятся `{#each}` по дескрипторам — новое необязательное поле
добавляется одной записью. Брейкпоинты и ширины живут в `minWidth`/`width`, а не в `{#if}`
в разметке. Составные поля (email и адрес) используют `kind: 'email'`; остальные —
`value`/`title`. Обязательные поля («Клиент», «Заявки», «Статус») имеют нестандартную разметку
(ссылка, счётчик, чипы) и остаются описанными в странице; их подписи и порядок тоже берутся
из реестра. Поведенческие тесты чистых правил — `client-fields.test.ts`, `sort-terms.test.ts`;
`page-toolbar.test.ts` и `modal-offset.test.ts` — строковые проверки контракта, а не доказательство AA.
