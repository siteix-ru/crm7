# Уведомления через MAX и Telegram

Stage 3.4.282 добавляет два независимых канала доставки рядом с Email. Бизнес-код
работает только с `App\Messaging\ChannelProvider`; конкретные API вынесены в
`MaxProvider` и `TelegramProvider`.

## Ключ шифрования

Токены ботов и секреты webhook сохраняются в `messenger_channels` только как
`Crypto::encrypt()` (AES-256-GCM, ключ `hash('sha256', APP_KEY)`).

- `APP_KEY` обязателен. Если он отсутствует, сохранение токена завершается
  ошибкой и **никакое открытое значение в БД не пишется**.
- При смене `APP_KEY` ранее сохранённые токены становятся нечитаемыми — введите
  их заново через панель. По возможности храните секрет в `api/config/.env` или
  в переменной окружения `APP_KEY` контейнера.
- Токены никогда не возвращаются API, не попадают в аудит, логи и сообщения
  об ошибках. Показывается только «токен сохранён» и маскированное значение.

## Настройка MAX

1. Создайте бота в MAX (платформа MAX для бизнеса) и скопируйте access token.
2. В CRM7: **Настройки → Мессенджеры → MAX**:
   - включите канал;
   - введите токен в поле «Новый токен» (пустое поле при сохранении не стирает
     действующий токен);
   - нажмите «Проверить соединение» — выполняется реальный `GET /me` на
     `https://platform-api2.max.ru` с заголовком `Authorization: <token>`.
     В ответе показываются имя и идентификатор бота, если API их вернул.
3. Удалите токен отдельной кнопкой с подтверждением — канал будет отключён.

### Webhook MAX

Webhook обязателен для привязки аккаунтов. URL должен быть HTTPS, порт 443,
сертификат доверенного центра.

1. Введите публичный HTTPS URL вида `https://<домен>/webhooks/max` и нажмите
   «Установить webhook». CRM7 создаст подписку `POST /subscriptions` с типами
   `message_created`, `bot_started` и случайным `secret`.
2. CRM7 проверяет заголовок `X-Max-Bot-Api-Secret` на каждой доставке.
3. MAX отписывает бот, если 8 часов нет успешного ответа — повторите установку.
4. Лимит MAX — не более 2 сообщений в секунду в один диалог; общий worker
   выдерживает интервал 550 мс и повторяет временные ошибки.

## Настройка Telegram

1. Создайте бота через BotFather и получите token.
2. **Настройки → Мессенджеры → Telegram**: включите канал, введите токен,
   нажмите «Проверить соединение» (`getMe`).
3. Установите webhook на `https://<домен>/webhooks/telegram` кнопкой
   «Установить webhook». CRM7 передаёт секрет в `secret_token`, обработчик
   проверяет заголовок `X-Telegram-Bot-Api-Secret-Token`.
4. Токен в URL не используется: Bot API получает его в пути запроса, но CRM7
   не логирует URL и не возвращает токен наружу.

## Привязка сотрудников

1. **Профиль → Уведомления → Привязка мессенджеров** → «Подключить».
2. CRM7 создаёт одноразовый код (5 минут, не более 5 попыток) и показывает его.
   В БД хранится только SHA-256 хеш кода.
3. Пользователь отправляет код боту:
   - MAX: через диплинк или сообщение с кодом (`bot_started` / `message_created`);
   - Telegram: `/start <код>` через webhook.
4. Идентификатор из входящего события используется только после проверки
   подлинности webhook и одноразового кода. Просто переданный пользователем ID
   владением не считается.
5. Повторные события отсекаются по `messenger_webhook_events`.
6. «Заменить» создаёт новый код, «Отвязать» удаляет связь.

## Выбор каналов уведомлений

В **Профиль → Уведомления** для каждого события есть отдельные флаги
`В системе`, `На e-mail`, `MAX`, `Telegram`. По умолчанию MAX и Telegram
выключены (opt-in). Правила CRM7 сохраняются: автор события не уведомляется,
внутренние комментарии не уходят клиентам, вложения в мессенджеры не отправляются.

## Очередь и диагностика

MAX и Telegram используют общую таблицу `email_queue` с колонкой `channel`;
Email продолжает использовать те же таблицы и свой worker. Канал worker'а
запускается из `api/bin/cron.php`.

Коды ошибок: `token_missing`, `auth_invalid`, `network_error`, `rate_limited`,
`api_error`, `bad_response`, `invalid_recipient`, `recipient_blocked`,
`channel_disabled`, `provider_exception`, `unknown_channel`.

Временные ошибки планируются через `next_attempt_at`: `Retry-After` или
`parameters.retry_after` имеет приоритет, при неизвестном формате ответа MAX
используется консервативный fallback, сетевые ошибки получают экспоненциальный
backoff. Задача не берётся в работу раньше назначенного времени; после
исчерпания попыток она переходит в `failed`. MAX и Telegram обрабатываются
отдельными проходами в предсказуемом порядке, поэтому медленный канал не
задерживает другой. Удаление токена дополнительно удаляет секрет webhook и
состояние дедупликации событий этого канала.

В технические логи не пишутся токены, содержимое сообщений и персональные
данные — только нормализованный код ошибки и идентификатор записи очереди.

## Ограничения тестирования

- Реальные запросы к Telegram в CI и локальных тестах не выполняются:
  используется mock HTTP transport.
- Реальный `GET /me` MAX и отправка тестового сообщения возможны только в
  разрешённой среде и только с токеном, введённым администратором через панель.
  Токен не запрашивается в чате и не включается в тестовые фикстуры.
